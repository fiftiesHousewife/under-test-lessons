# Testing old Java code: a journey

**Start here.** One deck, read aloud, before all the other lessons: what each kind of test and each technique is for,
as answers to the questions a team asks of old code, with every lesson linked.

Old code works and people rely on it, but nobody is sure what a change will break, and it usually has no tests, or tests
nobody can trust. This lesson is the start of the journey: it takes the questions in the order a team meets them (is it
safe to run, can we trust its tests, what does it do today, what should it do, how do we test without the real systems,
how do we change it safely, how do we make every new test count) and points each to the lessons that answer it.

There is no example to run: this lesson is its slides, and their narration.
