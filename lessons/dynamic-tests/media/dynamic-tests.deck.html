What are dynamic tests?

  • Tests made while the tests run, from data: one test per file, row or case
  • Each one runs, passes or fails, and is reported on its own
  • Add data, and you add tests, with no new test code
Dynamic tests are made while the tests run, from data: one test for each file, row, or case. Each one runs, passes or fails, and is reported on its own. Add more data, and you add more tests, with no new test code.

Our example: names on letters

  • Customer records are stored as SURNAME,FIRST NAME,TITLE, in capitals
  • Letters need the name written properly: Mr Patrick O'Brien
  • A folder of example files shows the expected name for each record
Our example writes names on letters. The old system stores customer records as surname, first name, and title, all in capitals. Letters need the name written properly, such as Mister Patrick O'Brien. And a folder of example files shows the expected name for each record.

Why one test per example

  • A loop stops at the first failure, hiding the rest
  • Its name never says which example broke
  • Old systems often come with folders of examples: turn each into a test
Why one test per example? A loop stops at the first failure, and hides the rest. Its name never says which example broke. And old systems often come with whole folders of examples, from regression packs and old bug reports. Each one deserves to be its own test.

How JUnit makes them

  • A method marked @TestFactory returns a stream of dynamic tests
  • Each dynamic test has a name and the code to run
  • JUnit runs and reports each one, like any other test
In JUnit, a method marked as a test factory returns a stream of dynamic tests. Each one has a name, and the code to run. JUnit runs each one, and reports it, just like any other test.

              When to use dynamic tests

              • When the cases live in files: regression packs, sample messages, old bug reports
              • Name each test after its file, so a failure points straight at it
              • For cases written in the test itself, parameterised tests are simpler
              When should you use dynamic tests? When the cases live in files: regression packs, sample messages, and old bug reports. Name each test after its file, so a failure points straight at it. And for cases written in the test itself, parameterised tests are simpler.

              Where they came from

              • Part of JUnit since JUnit 5, in 2017
              • They make tests from data found at run time, which fixed test methods can't
              • JUnit 6 is the current generation
              Dynamic tests have been part of JUnit since JUnit 5, in 2017. They make tests from data found while the tests run, which fixed test methods can't do. JUnit 6 is the current generation.
